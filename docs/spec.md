## 1. 概要

仕事中の「なんかやる気出ない」を、睡眠・体調・時間帯・天気・換気や休憩の経過から説明し、集中が下がる時間をうまくやり過ごすための Web サイト。

- **スタンス**：集中できている時間は放っておく。集中が下がる時間（ペースダウン時間）だけを予測し、対処法を出す
- **ターゲット**：在宅／ハイブリッドで PC 作業が中心の会社員・フリーランス
- **利用形態**：PC ブラウザのピン留めタブで 1 日開いておく

## 2. v1 の範囲と方針

| 項目 | v1 の決定 |
|---|---|
| 形態 | Web サイト（PC 中心。スマホ幅でも崩れない） |
| ログイン | **なし**。データはブラウザの localStorage に保存 |
| 通知 | タブを開いている間のブラウザ通知のみ（Notification API）。Web Push は v2 以降 |
| タスクの組み替え | 「この時間は軽い作業向き」と提案するだけ |
| カレンダー連携 | **v1 では入れない**（下記 2-1） |
| 天気 | Open-Meteo（API キー不要）をブラウザから直接呼ぶ。気温は気象庁アメダスの実測で補正する |

### 2-1. カレンダー連携を v1 から外す理由

- Google／Outlook の予定を読むには、各社アカウントでの OAuth 認可が必要で、「ログイン不要」の方針と衝突する
- プロトタイプでは設定画面に Google カレンダー・Outlook の連携 UI と、グラフのホバーで予定名を出す表示まで作成済み。v2 でログイン（サーバー保存）を入れるときに、この UI をそのまま使う
- v2 で必要になるもの：Google Calendar API（`calendar.readonly`）、Microsoft Graph（`Calendars.Read`）、トークンを保持するサーバー

## 3. 用語

| 用語 | 意味 |
|---|---|
| 今日のコンディション | その日に力を出しやすい環境かを 0〜100% で表した値（HERO） |
| ペースダウン時間 | コンディションが当日平均より下がる時間帯。下がり幅で 2 段階：「ややペースダウン」「ペースダウン」 |
| ふりかえり | 試した対処が効いたかを記録する場所 |

「要注意」「警戒」は使わない（調査結果は v2 の A 章を参照。集中・エネルギー系のアプリは自然な波として伝え、行動を勧める言い方が主流）。

### 3-1. 文言の方針

- 「下がる」「戻る」などは主語を書く（「集中が落ちやすくなります」）。グラフを前提にした比喩（谷・山）は使わない
- 食後の時間帯は「食後に眠くなりやすい時間」と書く
- 数字と日本語の間に半角スペースを入れない（グラフ上のラベルは除く）

## 4. 画面

1 ページ構成（SPA）。チェックイン・「集中切れた」・設定・初回設定はモーダルで表示する。

```
[初回のみ] 0.初回設定 → 1.チェックイン
[毎日] その日最初の表示で 1.チェックイン（スキップ可）
2.ホーム（常駐） ─┬→ 3.「集中切れた」（モーダル）
                  └→ 5.設定（モーダル）
```

### 4-0. 初回設定（5 ステップ、各ステップでスキップ可）

| ステップ | 項目 | 既定値 |
|---|---|---|
| 1 | 仕事する時間（15 分刻み） | 9:00–18:00 |
| 2 | いつもの就寝・起床時刻、朝型・夜型（朝型／どちらでもない／夜型） | 0:00／7:00、どちらでもない |
| 3 | からだのこと：生物学的な性別（女性／男性）。女性なら最終月経の開始日と周期（20〜45 日） | 未回答／周期 28 日 |
| 4 | 場所（市区町村の検索、または現在地） | — |
| 5 | 通知（N1／N2／N3 の個別トグル＋ブラウザの許可） | N1・N2 オン、N3 オフ |

冷暖房は聞かない（毎朝のチェックインで聞く）。

### 4-1. 朝のチェックイン

| 項目 | 入力 | 備考 |
|---|---|---|
| 寝た時刻・起きた時刻 | 時刻 ×2 | 初期値はいつもの就寝・起床時刻。睡眠時間を自動表示 |
| 睡眠の質 | 顔アイコン 3 段階（よく眠れた／ふつう／いまいち） | 必須 |
| 今の体調 | 顔アイコン 3 段階（いい／ふつう／いまいち） | 必須 |
| 気になる症状 | チップ複数選択（頭痛／頭が重い／目が疲れてる／だるい／肩・首こり／鼻・のど） | 任意。体調が「ふつう」「いまいち」で展開、「いい」なら「症状を追加」リンクのみ |
| 月経 | ［今日から始まった］トグル | 生物学的な性別で女性を選んだ人だけ。オンにすると最終月経の開始日を今日にする（外すと元の日に戻す） |
| 今日の冷暖房 | 暖房／冷房／使わない | 初期値は前日の回答 |
| 設定温度 | −／＋ で 0.5℃刻み（16〜30℃） | 暖房・冷房のときだけ表示。初期値は暖房 21℃、冷房 26℃ |

- ボタン：［今日をはじめる］／［あとで］（いつもの時刻・ふつうで仮計算し、HERO に「仮」バッジ）
- ホームの［チェックインを編集］から開いた場合は、今日の回答が入った状態で開き、［保存する］／［キャンセル］

### 4-2. ホーム

PC（幅 881px 以上かつ高さ 620px 以上）では **ページ全体をスクロールさせず 1 画面に収める**。グラフが残りの高さいっぱいに伸び、ウィンドウのリサイズで描き直す。それ未満の画面では縦スクロールを許可する。

レイアウト：左列＝今日のコンディション＋曲線＋いまの詳細、右列＝今の状態＋ふりかえり＋［集中切れた］ボタン。

#### (1) 今日のコンディション（HERO）

- 大きな % ＋見出し＋サブコピー「睡眠・体調・天気から計算した、今日の集中しやすさ」
- 帯ごとの一言（80 以上／60〜79／40〜59／39 以下）
- 「内訳を見る」：減点の大きい要因を上位 3 つ

#### (2) 時間帯ごとのコンディション（曲線グラフ）

- 横軸：**仕事時間の前後 2 時間**（既定 7:00〜20:00）。仕事時間の外は背景を薄く塗る
- 縦軸：コンディション 0〜100%（目盛り 0／50／100）
- 現在時刻より前は灰色、以降はアクセント色。現在時刻に縦線と「いま ◯%」
- ペースダウン区間は曲線の下を淡い紫で塗り、上にラベル
- 当日平均（＝HERO）を破線で表示
- 記録（換気・休憩・水・昼食）をアイコンでグラフ下部に表示（`icons/wind.svg`・`coffee.svg`・`droplet.svg`、昼食は Lucide の utensils）
- アイコンを押すと記録の編集モーダル：時刻（5 分刻み、いまより後は不可）、休憩は長さも変更可、削除（トーストで取り消し可）
- **ホバー（タップ）で 1 時間単位の詳細**：時刻、%、ペースダウン中ならその種類と原因、上げ下げした要因（例：食後のリズム −10）、気温・室内湿度・気圧・日射。半透明＋背景ぼかしで下のグラフが透ける。クリックで固定、左右キーで 1 時間ずつ移動

#### (3) いまの詳細（グラフの下）

- いまの時刻、%、状態（「ややペースダウン中（食後のリズム）・14:00 まで」または「通常ペース」）
- ペースダウン中は対処のヒントを表示し、背景を淡い紫にする
- いまの要因（上げ下げ）をチップで表示
- 次のペースダウン時間（なければ「このあとペースダウンの予報はありません」）

#### (4) 今の状態

| 表示 | 内容 |
|---|---|
| 天気 | 天気・気温・気圧と 3 時間後の変化。気温は近くのアメダスの実測があればそれを出し、観測点の名前と距離を添える（なければ「気温は予報」） |
| 室内の湿度 | 推定値（冷暖房時はその旨）。40% 未満「乾燥ぎみ」、30% 未満「かなり乾燥」、70% 超は室温 25℃ 以上で「蒸し暑い」、25℃ 未満で「湿気が多め」（室温は冷暖房中なら設定温度、なしなら外気温） |
| 冷暖房 | 暖房／冷房／なし の切り替え＋設定温度の −／＋。変更で即再計算 |
| 換気から／休憩から | 経過時間。換気 1.5h 超・休憩 2h 超で色を変える |

ワンタップ記録：［窓開けた］［休憩する］（長さを選ぶモーダル）［水飲んだ］［ご飯食べた］（グラフと同じアイコン）。［ご飯食べた］は、食後に眠くなりやすい時刻（5-3 の t_dip）を動かす。ホバー（フォーカス）で「いま食べると、15分後の12:15から13:15までがペースダウンの時間になります（最低63%）」のように、いま食べた場合の予報を出す（記録を仮に足して再計算）。10〜16 時以外は「予報に使いません」と出す。押すと経過をリセットし再計算、5 秒間「取り消す」付きのトースト。

#### (5) ふりかえり

- 通知・バッジは出さない
- 「やってみる」の 15 分後、試した対処をまとめて 1 枚のカードで聞く：［ラクになった］［変わらない］［わからない］
- 答えなければ 2 時間で、または次の「集中切れた」で静かに消える（未回答として記録）
- 「よく効く対処：窓を開ける（2 回中 2 回ラクに）」の要約、直近 3 件の結果
- 中身が多いときは、この欄の中だけスクロールする

#### (6) ［集中切れた］ボタン

PC では右列の最下部、スマホ幅では画面下に固定。

### 4-3. 「集中切れた」

1. **症状**：眠い／ぼーっとする／目が疲れる／頭痛／イライラ／やる気が出ない／MTG後でぐったり（複数可）→［原因を見る］
2. **やってみよう**（今の状況に合いそうな順に最大 3 件）
   - 各カードは **対処法を太字で一番上** に表示し、その下に小さく「原因：◯◯ ●●○」と判断理由
   - ［やってみる］は **複数押せる**。押してもモーダルは閉じず「やる予定・押すと取り消し」に変わる。もう一度押すと取り消し
   - 対処に対応する記録（換気・休憩・水）は自動で入る。休憩は 5 分として記録する
   - 下部：［どれも違う］（症状だけ記録）／［閉じる］
- 「医療機関へ」の文言は入れない

### 4-5. 設定

仕事時間、いつもの就寝・起床時刻、朝型・夜型、からだのこと（生物学的な性別・最終月経・周期）、場所、通知（N1〜N3）、データ（JSON をコピー／すべて削除。削除はページ内で確認）。冷暖房は置かない。カレンダー連携は v2。

### 4-6. 通知（タブを開いている間のみ）

| ID | 内容 | 既定 |
|---|---|---|
| N1 | ペースダウン時間の 5 分前「まもなくペースダウン時間です」 | オン |
| N2 | 仕事開始を過ぎてもチェックイン未回答なら 1 回 | オン |
| N3 | ペースダウン中で換気 90 分超または休憩 120 分超のとき「換気か休憩をどうぞ」 | オフ |

効果確認の通知は出さない。1 時間に最大 1 件。

## 5. 算出ロジック

時刻はすべて「その日の 0 時からの時間（小数）」で扱う。曲線は 15 分刻みで計算する（ホバー表示は 1 時間刻みで点を拾う）。

### 5-1. 推定室内湿度

外気の水蒸気圧 e は室内でも変わらないと仮定する。

```
es(T) = 6.112 × exp(17.62·T / (243.12 + T))     [hPa]
e     = RH_out/100 × es(T_out)
暖房：RH_in = e / es(設定温度) × 100
冷房：RH_in = clamp(e / es(設定温度) × 100, 40, 65)
なし：RH_in = RH_out
```

例：外気 5℃・50%、暖房 21℃ → 約 18%。

### 5-2. 今日のコンディション

`HERO = clamp(100 − Σ減点, 10, 100)`

| 要因 | 減点 | 上限 |
|---|---|---|
| 睡眠時間 h | max(0, 7 − h) × 8 | 25 |
| 睡眠の質 | 0／4／10 | 10 |
| 起床時刻のずれ | 1h 以上 3、2h 以上 6 | 6 |
| 体調 | 0／5／12 | 12 |
| 症状 | 1 つにつき 3 | 9 |
| 気圧低下（仕事時間内の 3 時間で最大の低下量） | 2hPa 以上 4、4hPa 以上 8 | 8 |
| 推定室内湿度（仕事時間の平均） | 30–40% 3、30% 未満 6、70% 超 4 | 6 |
| 暑さ・寒さ | 冷暖房なしで仕事時間の平均気温が 28℃超または 12℃未満 5 | 5 |
| 日照 | 仕事時間の平均雲量 85% 以上 3 | 3 |
| 月経周期 | 月経 1〜2 日目 10、3〜5 日目 5、次の月経の前 7 日 6 | 10 |

- 月経周期は、最終月経の開始日を 1 日目として数える。周期を過ぎたら同じ周期で繰り返すとみなす（予測）。女性以外・未入力・未来の日付なら使わない

### 5-3. 時間帯ごとの曲線

```
D(t) = grog + morning + lunch + second + fatigue + vent + brk + sun + press + heat
grog    = −15·exp(−τ/0.75)                         τ = 起床からの経過時間
morning = 6·sin(π·clamp(τ−1, 0, 5)/5)
lunch   = −10·k·exp(−(t−t_dip)²/(2·0.7²))           t_dip = 今日の「ご飯食べた」（10〜16 時の最新）+0.75。記録がない日は lunch = 0
                                                  k = min(1.6, 1 + max(0, 7−睡眠h)·0.15)
second  = 4·exp(−(t−t_2nd)²/(2·1.2²))              t_2nd = 起床 + 10.5
fatigue = −max(0, τ−10)
vent    = −min(8, max(0, (換気からの経過分 − 60)/10))
brk     = −min(8, max(0, (休憩からの経過分 − 90)/8))
sun     = −3   日射 > 600W/m² かつ 13〜17 時
press   = −4   前後 1.5 時間の気圧低下が 2hPa 以上
heat    = −3   冷暖房なしで、その時刻の気温が 28℃超または 12℃未満
C(t)    = clamp(HERO + D(t) − 仕事時間内の D の平均, 5, 100)
```

- 朝型・夜型で曲線の形を変える（τ は起床からの時間）

| | grog の時定数 | morning の開始 | second の高さ・位置 | fatigue の開始 |
|---|---|---|---|---|
| 朝型 | 0.5h | τ−0.5 | 3・起床＋9.5h | τ>9 |
| どちらでもない（上の式） | 0.75h | τ−1 | 4・起床＋10.5h | τ>10 |
| 夜型 | 1.25h | τ−2 | 6・起床＋11.5h | τ>11 |

- 休憩は「休憩する」で 5・15・30・60 分から長さを選ぶ。休憩中は経過 0、終わった時刻（記録時刻＋長さ）から数える
- 曲線は起床時刻（チェックインの起きた時刻）から描く。起きる前の時間は横軸だけ残し、線は描かない。仕事時間内の平均も起床後だけで計算する。起床が仕事の終わりより後のときは全体を描く
- 換気・休憩の記録がない場合の起点は仕事開始時刻。未来は「このまま記録がなければ」で延長する
- `heat` はプロトタイプで追加した項。表示名は気温 20℃以上なら「暑い」、未満なら「寒い」

### 5-4. ペースダウン区間

- 仕事時間内で `C(t) ≤ HERO − 8` が 30 分以上続く区間を「ややペースダウン」、そのうち `HERO − 15` 以下を含む区間を「ペースダウン」
- 区間の原因＝最も低い点で最も大きく押し下げている項（grog／lunch／vent／brk／sun／press／fatigue／heat）
- 1 日に表示するのは下がり幅の大きい順に最大 3 区間

### 5-5. 「集中切れた」の候補スコア

各原因に 0〜1 のスコアを付け、上位 3 件（0.1 超）を表示する。確度は 0.66 以上 ●●●、0.4 以上 ●●○、それ以外 ●○○。

| 原因 | 基本スコア | 関連症状（各 +0.15） | 対処（記録） |
|---|---|---|---|
| 寝不足 | 睡眠 6h 未満 0.6／6.5h 未満 0.3、質いまいち +0.25 | 眠い、ぼーっとする | 15 分以内の仮眠、または外の光を浴びて 5 分歩く |
| 昼食後の眠気 | t_dip ± 1h で 0.55 | 眠い | 5 分歩く、または立って作業する（休憩） |
| 換気不足 | 換気から 90 分超で 0.4〜0.7、60 分超 0.2 | ぼーっとする、頭痛 | 窓を 5 分開けて、深呼吸を 3 回（換気） |
| 明るすぎ | sun 発生中 0.5、日射 450 超 0.2 | 目が疲れる | カーテンを閉めるか、画面の明るさを下げる |
| 乾燥 | 室内湿度 25% 未満 0.6、35% 未満 0.45 | 目が疲れる、頭痛 | コップ 1 杯の水を飲む。目薬もおすすめ（水） |
| 暑い／寒い | 冷暖房なしで気温が範囲外 0.5 | イライラ | 冷房を入れるか首元を冷やす／暖房を入れるか 1 枚羽織る |
| 休憩不足 | 休憩から 2h 超で 0.45〜0.7、1.5h 超 0.2 | 目が疲れる、イライラ | 5 分休憩。遠くを見て、肩を回す（休憩） |
| 気圧の低下 | 低下 2hPa 以上 0.5、1hPa 以上 0.2 | 頭痛、ぼーっとする | 考える作業を後回しにして、整理や片付けに切り替える |
| MTG疲れ | 「MTG後でぐったり」を選んだら 0.6 | MTG後でぐったり | 画面から離れて 5 分歩くかストレッチ。戻ったら次の作業の「最初の 1 手」だけやる（休憩） |
| タスクが曖昧 | 他がすべて 0.3 未満、または「やる気が出ない」単独で 0.5、それ以外 0.1 | やる気が出ない | 次の一歩を 1 行だけ書き出して、25 分だけやってみる |

ふりかえりで「ラクになった」1 件ごとに +0.1、「変わらない」1 件ごとに −0.1 を、その原因に加える。

## 6. データ（localStorage）

| キー | 内容 |
|---|---|
| `settings` | 仕事時間、就寝・起床、場所（名前・緯度経度）、通知設定、朝型・夜型、生物学的な性別・最終月経の開始日・周期 |
| `checkins` | 日付ごと：就寝、起床、睡眠の質、体調、症状、冷暖房、設定温度、スキップ有無、今日から月経（と上書き前の開始日） |
| `logs` | 日付ごと：記録（window／break／water／meal／slump）と時刻、break は長さ（分）、slump は症状も |
| `remedies` | 日付ごと：原因、対処、時刻、結果（better／same／unknown／expired／未回答） |
| `weatherCache` | 場所と日付ごとの時間別予報。1 時間ごとに更新 |

## 7. 外部 API

| 用途 | API |
|---|---|
| 時間別の天気 | `https://api.open-meteo.com/v1/forecast`（`temperature_2m, relative_humidity_2m, pressure_msl, shortwave_radiation, cloud_cover`、`timezone=Asia/Tokyo`） |
| 気温の実測 | 気象庁アメダス `https://www.jma.go.jp/bosai/amedas/`（`const/amedastable.json` から気温を測っている 30 km 以内で最寄りの観測点を選び、`data/latest_time.txt` と `data/point/{観測点}/{YYYYMMDD_HH}.json` で最新の気温を 10 分ごとに取得） |
| 市区町村の検索 | `https://geocoding-api.open-meteo.com/v1/search?name=…&language=ja&countryCode=JP` |

予報の気温は数度外れることがある。1 時間以内の実測があれば「実測 − その時刻の予報」の差を、観測時刻までの予報にはそのまま、その後は 4 時間かけて 0 になるように足す。曲線・減点・湿度の判定はすべて補正後の気温で計算する。

## 8. v2 以降の候補

- ログイン＋サーバー保存（端末をまたいだ記録、振り返り分析）
- カレンダー連携（Google／Outlook）と、ペースダウン時間に重い予定がある場合の組み替え提案
- カレンダー連携時、MTG の終了後にグラフを下げる（MTG 疲れの項）。v1 は「集中切れた」の症状「MTG後でぐったり」だけ。想定している状況は、話す・聞く・気を遣うことによる消耗とオンライン会議の疲れ（座りっぱなし・画面の見続け）
- Web Push（タブを閉じていても通知）
- 個人ごとの傾向の学習（ふりかえり結果で曲線の係数を補正）
- センサー連携（SwitchBot、Nature Remo など）
